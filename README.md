# dsh-cost-meter

> A [DeepSeek Harness](https://deepseek-harness.github.io/deepseek-harness/guide/quickstart) client plugin that puts **your real account wallet** and an **official-price estimate of the current session** in the composer dock — plus what the turn in progress has cost so far.
>
> 一个 DeepSeek Harness 插件：在输入框下方显示**账号钱包真实余额**、**本次会话按官方价目表算出的花费**，以及**本轮花费**。

```
¥94.25 · ≈¥5.10                                    ← 状态栏里的 pill（点一下展开）
┌──────────────────────────────┐
│ ⟲ 账号钱包              ¥94.25 │
│ ─────────────────────────────  │
│ 充值余额                ¥94.25 │
│ 赠送额度                 ¥0.00 │
│ 余额合计                ¥94.25 │
│ 本次会话 · 官网价       ≈¥5.10 │
│ 本轮花费        ≈¥0.033（进行中）│
└──────────────────────────────┘
```

## 它解决什么问题

Harness 自带的统计只告诉你「用了多少 token」，不告诉你「花了多少钱」。这个插件补上后者，并且**不编数字**：

- 钱包余额直接读账号服务（`ctx.remote.account.getBalance`），是真钱；
- 花费按 [DeepSeek 官方价目表](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 算，**含高峰/空闲时段**（高峰 = 空闲 ×2）与中国法定节假日；
- 官方改价时，用**钱包实际扣的钱**反推一个修正系数，pill 自己跟上，不需要你改代码。

插件不接触任何凭据：余额调用走 Host 已持有的账号授权，客户端拿不到令牌。

## 安装

前提：DeepSeek Harness 桌面版（开发版本 `0.2.0-rc.2`）。

**方式一（推荐）**：侧边栏 → 插件管理 → 从**本地目录路径**安装 → 填本目录的绝对路径。安装结果应为 `applied`；若状态栏没出现，刷新页面。

**方式二（命令行）**：

```bash
dsh plugin --profile <profile> add <本目录绝对路径>
```

装完后 `dsh.profile.bundles` 会自动带上本包；改完代码刷新页面即可（本地目录是软链，不用重装）。

## 数字怎么来的

| 数字 | 来源 |
|---|---|
| 充值余额 / 赠送额度 / 余额合计 | `ctx.remote.account.getBalance()` —— 平台钱包，两位小数，小于一分显示 `<¥0.01` |
| 本次会话 · 官网价 | 官方单价 × 会话的 token 分桶（未命中输入 / 缓存命中 / 缓存写入 / 输出），**逐个观测增量按各自发生时的时段计价** |
| 本轮花费 | 同上，但只统计「本轮」——见下 |

- **峰谷**：北京时间周一至周五 09:00–12:00、14:00–18:00 为高峰；周末与法定节假日全天空闲（节假日表内置，跨年会提示更新）。
- **轮次边界**：取 `useSession(s => s.running)` 的上升沿。页面刷新**不会**把一轮切成两半（挂载不算边界——这条是审计出问题后修的）。
- **模型**：取自 `modelSelection.lastUsed`；成本按模型分别累计，会话中途换模型不会互相串味。

## 自我校准（改价了怎么办）

每个观测窗口都会产生一对样本：`(官方表预测的钱, 钱包实际掉的钱, 窗口秒数)`，最近 24 组做一次两项回归：

```
实际扣费 ≈ r × 窗口秒数 + k × 官方表预测
            ↑ 时间项              ↑ 价格项
```

- 官方**涨价** → 只动 `k` → pill 自动按 `k` 修正；
- **另一台设备**在花同一个钱包 → 只动 `r` → `k` 保持 1.00，不会被误判成涨价。

闸门：样本不足、样本成本没有差异（斜率无法辨认）、残差过大时**一律不修正**；倍率钳制在 ×0.25–×4；`AUTO_CALIBRATE = false` 可完全关闭。更新 `RATES` 时记得同时改 `RATES_VERSION`，版本一变旧系数作废。

## 刷新策略

| 场景 | 频率 |
|---|---|
| 会话正在跑 | 5 秒 |
| 弹框打开着 | 5 秒（有人在看就不退避） |
| 空闲且一直没动静 | 每安静一分钟翻倍，40 秒封顶 |
| 余额变动 / 轮次起止 / 切回前台 / 窗口重新聚焦 | 立刻读一次 |
| 页面切到后台 | 暂停 |

本机会话的花费走推送（用量事件一到就读，亚秒级）；轮询只用于发现**推送看不到的花钱**（别的会话、别的设备）。平台没有余额推送接口，这是 API 层面的限制。

## 配置

都在 `client.js` 顶部：

```js
const RATES = { ... }              // 官方单价（人民币 / 百万 tokens）
const RATES_VERSION = '2026-09-10' // 价目表修订日；改价后同时更新这两项
const HOLIDAYS = [ ... ]           // 法定节假日（全天按空闲计价）
const RUNNING_INTERVAL_MS = 5000   // 运行中轮询
const IDLE_INTERVAL_MS = 5000      // 空闲基准
const IDLE_MAX_INTERVAL_MS = 40000 // 空闲退避上限
const AUTO_CALIBRATE = true        // 是否应用实测修正
```

## 已知限制

- **页面打开前的那段用量**只能整笔按打开时刻的时段计价（跨峰谷时最多差 2×）。逐请求精确计价需要 Host 侧投影，尚未实现。
- **缓存写入**没有官方独立价目，按「未命中输入」计价；本账号实测写入量为 0，该假设未生效。
- 钱包是**账号级**的：别的设备/会话的花费会影响校准样本（回归会把它分离到 `r`，但仍会引入噪声）。
- 修正系数存在 `localStorage`，换浏览器/清缓存后需要重新积累样本。
- 只在 Harness **桌面版**上验证过（依赖账号 Remote 与 `conversation.composer.dock` 插槽）。
